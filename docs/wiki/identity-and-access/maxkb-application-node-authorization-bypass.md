# MaxKB Application Node Authorization Bypass

## Current Understanding

The [September 21 topic collector source](../../../raw/processed/2026-09-21/ai-security-wiki-topic-news-collector-2026-09-21T233156Z.json) records [CVE-2026-77520](https://cveawg.mitre.org/api/cve/CVE-2026-77520) for MaxKB 2.10.2-lts and earlier. Broad MaxKB product context belongs upstream; this page owns application identifier disclosure and workflow invocation authorization.

A normal user in the same workspace can obtain another user's `application_id` from the homepage application question-ranking endpoint when the published victim application has ranking activity and the attacker knows or guesses its name. The attacker can place that identifier in an attacker-owned workflow application node, trigger the workflow, receive output generated by the victim application, and create durable `application_chat` and `application_chat_record` rows under the victim application because save and runtime paths do not verify permission to use the referenced application. No fixed version was available in the captured record.

## Security Impact

- Threat: leaked application identifiers can authorize workflow invocation and persisted chat creation under another application.
- Affected boundary: MaxKB 2.10.2-lts and earlier; homepage ranking endpoint and workflow application-node runtime.
- Exploit or incident status: public GitHub advisory; no local exploitation evidence is recorded.
- Mitigation state: no fixed version identified; suppress unauthorized application IDs and re-check application-use permission at workflow save and runtime.
- Confidence: high for advisory existence and affected range; fixed-version confidence is unavailable.
- Residual risk: assistant application IDs are authority-bearing references when workflows can invoke them indirectly.
