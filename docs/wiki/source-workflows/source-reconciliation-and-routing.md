# Source Reconciliation And Routing

## Current Understanding

Source reconciliation applies the authority order in [schema.md](../schema.md), normalizes aliases and advisory identifiers, keeps source-specific claims attributed, and preserves unresolved contradictions as open questions.

Federation routing is mandatory before local leaf creation. ai-wiki owns broad AI ecosystem entities. ai-dev-wiki owns general AI-assisted development practices. This wiki owns only security-specific threat, control, assurance, governance, and incident analysis that needs an independent maintenance path.

## Practice Boundaries

- Prefer primary advisories, official standards, vulnerability databases, incident reports, code, tests, and peer-reviewed or directly reproducible research.
- Distinguish affected product facts from the locally owned security analysis.
- Normalize duplicate vulnerability names, aliases, and identifiers into the best durable local page.
- Preserve version scope, exploit status, date evidence, mitigation state, and confidence.
- Link upstream leaves at the point where local analysis depends on them.
- Record unclear ownership or conflicting evidence in open-decisions.md.
