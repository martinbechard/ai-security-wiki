# Kiota AI Host Manifest File Boundary Disclosure

## Current Understanding

The [August 17 topic news collector source](../../../raw/processed/2026-08-17/ai-security-wiki-topic-news-collector-2026-08-17T233246Z.json) records CVE-2026-73851 / GHSA-p5rm-jg5c-8c77 for Microsoft Kiota. Kiota and OpenAPI code-generation practice belong in the upstream AI development wiki; this local page owns the AI-host package-boundary and generated-manifest supply-chain risk.

Before Kiota 1.29.1 and 1.34.0, an attacker who controlled or tampered with an OpenAPI description could supply file references that resolve outside the intended manifest package. The collector records path traversal, absolute paths, `file:` URIs, and HTTP(S) URIs as relevant reference forms. When the generated manifest is deployed and consumed by an AI host, the manifest can include or disclose files outside the intended package boundary.

Generated tool manifests are AI supply-chain artifacts. They need the same containment expectations as dependencies and model artifacts: input schema provenance, path normalization, external-reference policy, reproducible packaging, and review before host consumption.

## Security Impact

- Threat: tampered OpenAPI input can smuggle external file references into an AI-host package and disclose unintended local or remote content.
- Affected boundary: Kiota before 1.29.1 and 1.34.0; generated manifest packages consumed by AI hosts.
- Exploit or incident status: public NVD and GitHub advisory references; no exploitation evidence is recorded by the collector.
- Mitigation state: use Kiota 1.29.1 or 1.34.0 or later, reject absolute and external file references in manifests, and review generated package contents before AI-host deployment.
- Confidence: high for dates, affected versions, and fixed versions from NVD and GitHub references.
- Residual risk: AI hosts need their own install-time package-boundary checks because generator-side fixes do not prove every consumed manifest was generated by a patched tool.
